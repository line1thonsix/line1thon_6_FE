# F-15 · F-16 확인 기록과 수동 테스트

기준: 2026-11-10 직접 읽은 [최신 Notion](https://app.notion.com/p/41438b8166de801dbdc1e957d6f5704e), [Figma PC](https://www.figma.com/design/a0ftKPjygZBABCAYHCTgU7/1호선톤-6팀?node-id=48-830)의 08 / 10 / 11 / 11-2.

## 기존 구현과 실제 변경

- F-15: 의견 입력/완료, 공백 거부, 기초 학습에서 미제공, 회고와 별도 저장, 새로고침 복구는 기존 구현을 유지했다. 앞뒤 공백도 포함하여 의견 입력 2,000자 제한을 검사하도록 보정했다. 의견은 프론트엔드 시연용 sessionStorage에만 보관한다. 실제 서버 저장/전송/판정 변경은 하지 않는다.
- F-15의 특정 비교 항목 연결은 선택사항이다. 현재 Figma의 전체 결과 아래 `의견 남기기`를 유지하며, 항목 선택 버튼이나 별도 문구를 추가하지 않았다.
- F-16: 기존 하단 읽기 전용 입력창을 결과 로드 성공 후 후속 질문 입력창으로 사용한다. 별도 진입 버튼이나 새 화면을 추가하지 않는다. 기존 질문/코드/유형/최초 생각/분석 결과는 수정하지 않는다.
- 공백만 입력은 거부, 입력 전체 최대 2,000자, 대화당 새 질문 5개. 최초 질문과 후속 질문은 동일 Mock 사용량 장부(게스트 일 30회 / IP 시간 60회)에 포함한다. 새 요청을 접수할 때 횟수를 사용하며 실패한 동일 요청의 재시도는 중복 차감하지 않는다. 이는 한 Mock 저장소를 한 게스트/IP로 간주하는 시뮬레이션이며 실제 인증/IP 제한이 아니다.
- 후속 질문은 원래 대화 ID에 연결된다. 별도 잠금/생각 재제출/재분석 없이 공개된 참고 관점과 이전 후속 대화를 사용한 고정 Mock 응답을 표시한다. 다른 주제도 차단하지 않고 Figma의 `다른 주제의 질문은 새 채팅에서 던져 보세요.`를 입력창 placeholder로 유지한다.
- 질문/응답 쌍은 개발용 Mock 저장소에 생성 후 보관한다. 초안/미확인 요청 ID는 별도 대화별 초안 키에 보관한다. 답변 선탑재는 하지 않으며 GET/POST 모두 서버 역할 Mock의 공개 가드를 거친다. 영구 서버 저장이나 실제 AI 응답은 아니다.

## 실행

`frontend/`에서 `npm run dev:mock`, 브라우저에 표시된 주소를 연다. 기존 대화는 사이드바나 학습 기록에서 다시 열 수 있다. `followUp=error-once`, `followUp=error`, `followUp=slow`는 개발용 Mock에서만 동작한다. 다른 시나리오와 함께 쓸 때는 쿼리를 `&`로 연결한다.

## 직접 확인할 항목

- [ ] 새 질문 전송 → 잠금/힌트 1·2에서 후속 질문이 보이지 않는지 확인한다. 기존 선택지·자동완성 보호·생각 검증이 유지되는지 확인한다.
- [ ] 생각 제출 → PENDING/FAILED에서는 답변/후속 대화가 공개되지 않고, DONE 및 비교 결과 로드 성공 후에만 하단 후속 질문을 작성할 수 있는지 확인한다.
- [ ] `의견 남기기` → 기존 하늘색 입력 → 작성 → 전송 완료 문구/말풍선을 확인한다. 빈 입력과 2,001자는 거부되고 2,000자는 허용되는지 확인한다. 최초 생각과 판정이 변하지 않는지 확인한다.
- [ ] 회고 작성/저장과 의견 작성/전송을 번갈아 진행하고 새로고침한다. 서로 덮어쓰지 않고 학습 기록 미리보기에는 회고만 표시되는지 확인한다.
- [ ] 후속 질문을 한글로 작성하고 Enter 전송, Shift+Enter 줄바꿈, IME 조합 중 Enter, 전송 버튼을 확인한다. 전송 중에는 입력/재전송이 차단되는지 확인한다.
- [ ] 공백만, 2,001자 입력을 거부하는지 확인한다. 코드 추가/질문 유형은 계속 비활성인지 확인한다.
- [ ] 후속 질문 성공 → 질문/답변이 같은 대화 아래 표시되고 입력창이 비워지는지 확인한다. 최초 비교 카드와 근거 펼침이 유지되는지 확인한다.
- [ ] 작성 중 새로고침 → 초안 복구. 전송 중 새로고침 → 같은 요청으로 복구하며 질문/답변이 중복되지 않는지 확인한다.
- [ ] `?followUp=error-once`에서 새 후속 질문을 보낸다. 오류 후 질문이 남고 `다시 시도해 주세요`로 한 번만 저장되는지 확인한다. `error`는 계속 실패, `slow`는 약 5초 지연이다.
- [ ] 후속 질문 5개 완료 후 전송이 비활성이고 직접 API 호출도 거부하는지 확인한다. 같은 완료 요청 재전송은 6번째 답변을 만들지 않는지 확인한다.
- [ ] 학습 기록 → 이전 SELF 대화 다시 열기 → 후속 대화/의견/회고 복구를 확인한다. 다른 대화로 이동해 초안과 답변이 섞이지 않는지 확인한다.
- [ ] 막힌 지점 미선택 → 힌트 1 → 2 → 기초 학습을 연다. 결과 로드 전 후속 질문 차단, 로드 후 질문 가능, 의견 버튼 없음, 회고 가능을 확인한다. 새로고침과 기록의 `기초 학습` 분류/성장 지표 제외를 확인한다.
- [ ] 다른 주제의 질문도 전송 가능하고, 새 채팅 안내 placeholder가 유지되는지 확인한다.

## 실제 백엔드 연동 시 남은 계약

로컬 docs의 API 명세/CSV는 후속 질문 엔드포인트를 정의하지 않는다. 최신 기능명세서와 동일 버전이라고 가정하지 않는다. 문서는 수정하지 않았다.

1. 개발 전용 `GET/POST /api/chats/{chatId}/follow-ups`와 `{ question, clientRequestId }`, `{ chatId, items: [{ id, question, answer }], remaining }`는 임시 Mock 계약이다. BE와 실제 경로·DTO·오류·동기/비동기 처리 방식·정렬을 확정해야 한다.
2. 실제 클라이언트에 `X-Guest-Token` 인증과 소유권 검사를 연결하고, 서버에서 공개 상태를 재검증한다. 클라이언트의 DONE/경로/남은 횟수 주장을 신뢰하면 안 된다.
3. 서버가 질문/코드/최초 생각/기준 답변/이전 후속 대화를 모아 모델에 전달해야 한다. 사용자 입력을 지시가 아닌 데이터로 분리하는 모델 호출은 아직 구현하지 않았다. 현재 응답은 고정 Mock이다.
4. 대화별 5회, 게스트 일 30회, 실제 IP 시간 60회 제한을 서버에서 원자적으로 적용한다. 실패/재시도 과금·카운트 정책과 멱등성 보존 기간을 합의한다. Mock의 동일 요청 재시도는 중복 차감하지 않는다.
5. 서버 DB 저장·취소/타임아웃·응답 유실 복구·보존 정책을 연결한다. 현재는 같은 브라우저 탭의 개발용 저장소이며 다중 탭/기기 동시성 보장은 없다.
6. F-15는 현재 네트워크 호출 없이 시연한다. 실제 `/feedback` 저장 및 선택적 비교 항목 연결을 도입할 경우 별도 승인이 필요한 개발 범위이며, 실제 전송 성공 후에만 서버 저장을 설명해야 한다.
7. 수정 대상 순서: BE 계약 확정 → `types/followUp.ts` / 응답 검증 → `api/followUps.ts` 인증 어댑터 → 복구/멱등성 컨트롤러 → MSW 계약 테스트 → 통합 검증. 기존 P0/P1 및 F-17 서버 계약도 함께 정렬한다.
