# F-18 내 데이터 삭제

## 확인한 최신 근거

- Notion 기능명세서 F-18 본문 직접 열람(2026-11-10~11): 게스트 더보기 전체 삭제, 학습 기록 항목별 삭제, 질문·코드·생각·결과 함께 삭제, 원문 없는 AI 호출 비용 기록 보존, 실행 전 되돌릴 수 없음 확인.
- 수용 테스트: 다른 게스트의 삭제 요청은 존재 여부를 드러내지 않는 404.
- Figma `14-1 · 전체 삭제 확인`(186:318), `14-2 · 기록 더보기`(186:130), `14-3 · 대화 삭제 확인`(186:404)의 실제 문구·버튼·배치 사용.

## 직접 실행한 UI 검증

- [x] PC 1440×900에서 학습 기록 더보기 → `이 대화 삭제` → 확인창 표시.
- [x] `취소`를 누르면 기록 유지, 게스트 전체 삭제 취소 시 작성 중 생각 유지.
- [x] 개발 Mock `?deletion=error-once&view=history`에서 첫 삭제 실패 후 확인창에 `다시 시도해 주세요`, 다시 `삭제` 시 성공.
- [x] 삭제 후 최근 대화·학습 기록에서 제거되고 새로고침 후에도 다시 나타나지 않음.
- [x] 모바일 390×844에서 사이드바 → 게스트 더보기 → 전체 삭제 확인창 → 성공 → 빈 기록 확인.
- [x] 모바일 전체 삭제 후 새로고침 시 빈 기록 유지, 브라우저 오류 로그 없음.
- [x] 확인창은 취소에 최초 초점을 두며 취소 후 메뉴 초점 복귀. 삭제 중 두 버튼은 비활성화.

위 검증은 새 탭에서 직접 만든 일회용 Mock 대화만 대상으로 했다. 실제 서버 데이터 삭제를 실행하지 않았다.

## 자동 검증

- 대화별 삭제 후 다른 대화 유지, 결과·후속 질문·힌트·분석·기초 학습 조회 404, 재진입·Mock 재생성 후에도 삭제 유지.
- 전체 삭제 성공/빈 저장소 재삭제, 실패 시 원본 유지와 재시도.
- 잘못된/없는 Mock 소유자 토큰 404, 별도 게스트 저장소 격리.
- 분석·기초 학습·후속 질문·새 질문 생성 중 삭제와 늦은 응답 차단.
- 로컬 생각·회고·의견·힌트·후속 질문 초안 정리, 다른 앱·API 작업 공간·다른 대화 보존.
- 운영 모드에서 Mock 삭제 플래그가 켜져 있어도 삭제 네트워크 요청이 발생하지 않음.
- Figma 확인 문구와 버튼, 처리 중 중복 요청 차단 및 오류 표시.

## 수동 재현 체크리스트

1. Mock 모드에서 질문 두 개 이상을 만들고 생각 초안을 적는다.
2. 학습 기록 항목 더보기 → `이 대화 삭제` → `취소`: 기록과 초안 유지 확인.
3. 다시 진입 → `삭제`: 해당 항목만 제거되고 다른 대화는 열리는지 확인.
4. 현재 대화를 삭제한 뒤 채팅으로 돌아가면 새 질문을 작성할 수 있는지 확인.
5. 게스트 더보기 → `전체 데이터 삭제` → `취소`/Escape: 아무 데이터도 삭제되지 않아야 한다.
6. 전체 삭제 확인 후 최근 대화·모든 기록 탭이 비고 새로고침·뒤로가기 후에도 삭제된 결과가 열리지 않는지 확인.
7. `?deletion=error-once`는 첫 실패 후 재시도, `?deletion=error`는 계속 실패와 취소, `?deletion=slow`는 처리 중 중복 클릭 차단 확인. URL에 `view=history`를 함께 사용할 수 있다.
8. 분석 지연(`analysis=slow`), 기초 학습 지연(`basicResult=slow`), 후속 질문 지연(`followUp=slow`) 중 삭제 후 늦은 응답으로 기록이나 답변이 다시 생기지 않는지 확인.
9. PC 1440×900·모바일 390px에서 메뉴 위치, 확인창, Tab/Escape, 취소 후 초점을 확인.

## Mock과 실제 백엔드의 구분

- 이번 삭제는 개발 환경(`DEV && VITE_ENABLE_MOCKS=true`)에서만 사용한다. 임시 MSW 경로는 `DELETE /api/chats/:chatId`와 `DELETE /api/chats`, 성공은 204이다. 확정 서버 계약으로 추가하지 않았다.
- `X-Mock-Guest-Token`은 이 탭의 Mock 저장소에만 속하는 시뮬레이션 토큰이다. 실제 API의 `X-Guest-Token` 인증이나 서버 소유자 검증을 대신하지 않는다.
- 전체 삭제는 같은 Mock 저장소만 처리하며 다른 탭/게스트 저장소, API 작업 공간, 다른 앱의 저장소를 지우지 않는다.
- 질문·코드·생각·결과 재생성에 필요한 상태, 힌트·기초 학습·후속 질문·요청 중복 방지의 콘텐츠, 로컬 초안·회고·의견을 함께 정리한다. 진행 중 작업은 결과를 공개/저장할 수 없게 차단한다.
- 콘텐츠 없는 사용량 타임스탬프와 Mock 소유자 식별자는 유지해 비용 한도를 삭제로 초기화하지 않는다. Mock에는 실제 AI 호출/청구 원장이 없으므로 실제 비용 기록을 보존했다고 주장하지 않는다.
- 성공 토스트나 실제 서버 삭제 완료 문구는 추가하지 않았다. 실패 시 기존 Figma 오류 문구를 사용한다.

## 실제 백엔드 연결 전 협의·검증

1. 대화별/게스트 전체 삭제의 실제 URL·HTTP method·성공/오류 응답·멱등 재시도 계약 확인. 현재 backend 클라이언트는 DELETE를 허용하지 않으며 확정 후 별도 어댑터로 추가해야 한다.
2. 인증된 게스트를 서버에서 결정하고, ID와 소유자를 함께 검증한다. 클라이언트가 보낸 owner 값은 신뢰하지 않으며 다른 소유자/없는 ID는 404로 통일한다.
3. 질문·코드·생각·AI 답변·분석·기초 학습·후속 대화·회고/의견·관련 캐시/초안을 트랜잭션/일관된 정책으로 삭제한다. 실제 회고/의견 저장은 현재도 시연 전용이다.
4. AI 작업 취소/세대 무효화와 완료 경합을 처리하고, 늦은 응답은 저장하거나 공개하지 않는다. 이미 발생한 AI 비용이 취소되는 것은 아니다.
5. AI 비용/사용량 기록은 원문 없이 유지하고, 삭제로 비용 제한을 우회할 수 없게 한다. 콘텐츠 없는 운영 기록의 보관 범위/기간은 팀에서 확정한다.
6. 서버 삭제 성공 확인 뒤 클라이언트 캐시·초안·최근 기록을 정리한다. 응답 유실·부분 실패·다중 탭 동기화 정책도 합의한다.
