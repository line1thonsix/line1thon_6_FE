# F-08/F-09 간소화 검증과 실제 API 연동 변경점

## 현재 동작

이번 사용자 확정 요구사항에 따라 전환 조건은 **서버에 저장된 힌트 2 공개 기록 하나**입니다. 막힌 지점은 기록용 선택사항이며 어려움 확인 체크박스와 ‘내 생각 적어 볼게요’ 버튼은 없습니다.
힌트 2의 기존 ‘그래도 잘 모르겠다면 기초 학습으로 이어서 설명해 드릴게요.’ 문장과 원형 화살표를 하나의 버튼으로 연결했습니다. 다른 문구/버튼/배지는 추가하지 않았습니다.

## 실행과 자동 검증

```sh
cd frontend
npm run dev:mock
npm run build
npm run lint
npm test
```

Vite 출력 주소를 사용합니다. 이번 브라우저 검증 주소는 `http://127.0.0.1:5174/`입니다. 기존 Mock 데이터는 탭 단위이므로 복구 테스트는 같은 탭에서 새로고침합니다.

- [x] 빌드 통과, 린트 경고 없음, 전체 테스트 **106개 통과**.
- [x] 힌트 0/1에서는 BASIC 전환 거부. 힌트 1을 건너뛴 힌트 2 요청도 거부.
- [x] 힌트 2만 공개하면 막힌 지점/어려움 확인 없이 BASIC 전환 및 F-12 결과 조회 가능.
- [x] 요청 본문의 level/막힌 지점/확인 여부를 덧붙여 서버 조건을 위조할 수 없음.
- [x] 이전 저장소의 stillDifficult=false는 새 전환·결과 복구를 막지 않음. 새 힌트 응답/디코더에서는 해당 필드를 제외.
- [x] 중복 요청, 다른 요청 ID 재시도, 전환 응답 유실과 새로고침에도 동일 전환 유지.
- [x] 생각 제출과 BASIC 전환 경합 시 한 경로만 확정. SELF 비교 경로와 BASIC의 성장 지표 제외 유지.
- [x] UI에서 삭제 버튼/확인 체크박스 없음. 힌트 1에서는 BASIC 버튼 없음. 힌트 2의 기존 안내 문장 전체가 버튼이며 요청 중/불확실 상태에서는 비활성.
- [x] F-17과 F-12 통합 테스트도 막힌 지점을 선택하지 않는 경로로 실행. 답변 잠금·비교·초안 보호 관련 기존 테스트 통과.

## 직접 확인할 수동 테스트 — 이번 수행 완료

| 확인 | 절차 | 기대 결과 / 실제 결과 |
| --- | --- | --- |
| [x] 힌트 1 | 예시 질문 → 힌트 탭 | 힌트 1, ‘힌트를 더 볼까요?’, 선택적 막힌 지점. 작성 복귀 버튼·어려움 체크박스·BASIC 전환 버튼 없음 |
| [x] 기존 입력창 | 힌트 1에서 생각 작성 → 살펴볼 지점 탭 → 힌트 탭 | 기존 입력창과 작성 내용 유지, 전송 가능 상태 유지 |
| [x] 힌트 1→2 | 막힌 지점을 고르지 않고 ‘힌트를 더 볼까요?’ 클릭 | 힌트 2와 기존 기초 학습 안내 버튼이 활성화. 별도 필수 입력 없음 |
| [x] 초안·공개 기록 복구 | 힌트 2에서 새로고침 → 이전 힌트 보기 → 새로고침 → 다시 힌트 2 | 초안과 보는 단계 복구, 힌트 2 공개 기록 보존, 1에서 BASIC 안내는 숨김 |
| [x] 미선택 BASIC 전환 | 막힌 지점 미선택 상태에서 안내 문장 클릭 | 기초 학습 결과 진입, 작성 중이던 생각은 ‘보관한 생각 초안’에 유지 |
| [x] BASIC 복구·기록 | BASIC 결과 새로고침 → 학습 기록 → 기초 학습 필터 | 같은 결과와 비활성 완료 입력창 복구. 기록은 기초 학습으로 분류 |
| [x] 선택사항 기록 | 다른 질문 → 힌트 1에서 막힌 지점 선택 → 힌트 2 → 새로고침 | 선택 상태를 복구하되 전환의 필수 조건으로 사용하지 않음 |
| [x] 직접 제출 | 힌트 2를 연 상태에서 기존 입력창에 30자 이상 생각 작성 후 Enter | BASIC 전환을 누르지 않으면 SELF 분석 → 비교 결과. 학습 기록의 비교 완료 필터에 표시 |
| [x] 전환 응답 실패 | 같은 탭에서 `?basic=error-once` → 새 질문 → 힌트 2만 공개 → 전환 | 첫 응답 실패 후 ‘전환 다시 확인하기’로 이미 확정된 BASIC 경로 복구. 막힌 지점 미선택이어도 복구 가능 |

브라우저에서 Mock API를 임의 호출하는 우회 검증은 별도로 수행하지 않았으며, 위의 서버 우회·중복·경합 조건은 MSW 통합 테스트로 확인했습니다. 이전 상태의 체크리스트는 `F17_TEST_CHECKLIST.md`에 이력으로 남기고 현재 동작 안내를 덧붙였습니다.

## 실제 백엔드 연동 시 바꿔야 할 부분 (아직 미연결)

| 영역 | 필요한 변경 |
| --- | --- |
| 서버 전환 검증 | 기존의 힌트 2 + 막힌 지점 + 어려움 확인 조건을 힌트 2 공개 기록으로 단순화. 클라이언트의 level 주장을 신뢰하지 않고 세션 소유 대화의 서버 저장 상태를 검사 |
| 서버 결과 접근 | BASIC 전환이 확정되었고 힌트 2 기록이 있으면 막힌 지점=null이어도 결과 허용. 잘못된 전환 ID·다른 소유자·전환 전 접근은 계속 거부 |
| 서버 복구 DTO | 선택하지 않은 막힌 지점을 null로 허용. stillDifficult는 필수 검증/권한 판단에서 제거. 힌트의 최대 공개 단계와 현재 보는 단계는 분리 |
| 클라이언트 어댑터 | 현재 `src/api/basicLearning.ts`, `src/api/hints.ts`는 개발 Mock 전용. 명세에 있는 `/api/chats/{chatId}/basic-mode` 등 실제 경로·인증·DTO는 팀과 확정한 뒤 연결. Mock의 `/basic-learning`을 실제 계약으로 간주하지 않음 |
| 클라이언트 디코더 | `src/api/hintState.ts`처럼 BASIC 메타데이터가 있어도 막힌 지점 선택/확인 값을 요구하지 않아야 함. 공개 단계 2와 순서대로 전달된 두 힌트는 검증 |
| 상태·원자성 | 중복 전환은 같은 결과, 생각 제출과 전환 중 하나만 확정. 확정된 BASIC은 성장 지표 제외를 유지. 실패 응답 후 조회로 실제 확정 상태 확인 |
| 서버 수용 테스트 | 힌트 0/1 거부, 1→2 순차 확인 후 미선택 전환 성공, 결과 잠금/소유권/동일 요청 재시도/동시 제출 경합/새로고침을 함께 검증 |

현재 코드는 실제 백엔드를 호출하지 않습니다. 기존 DEV + VITE_ENABLE_MOCKS 조건과 Mock 저장 범위를 유지했습니다. 서버 파일명이나 실제 인증 계약은 이 작업에서 임의로 확정하지 않았습니다.
