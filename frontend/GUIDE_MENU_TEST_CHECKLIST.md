# 이용 안내 · 게스트 더보기 확인

기준: 최신 Notion 기능명세서 직접 열람 및 Figma PC `13 · 이용 안내`(170:830), `14 · 더보기 메뉴 (게스트)`(186:236).

## 직접 확인한 항목

- [x] 1440×900: 안내 본문 x460/y100, 776×668, 네 단계 2열 배치와 주의 문구.
- [x] 안내 예시는 정적 그림이며 질문 제출이나 실제 답변 조회를 실행하지 않음.
- [x] 안내 이동 → 브라우저 뒤로/앞으로 → 새로고침 시 URL에 맞는 화면 표시.
- [x] 질문 초안 작성 → 안내 이동 → 뒤로가기 시 초안 유지.
- [x] 390×844: 안내 1열 배치, 문서 가로 넘침 없음, 본문 세로 스크롤.
- [x] 모바일 사이드바 → 학습 기록 이동 시 메뉴 닫힘, 뒤로가기·새로고침 시 안내 복원.
- [x] 바깥 클릭·Escape로 모바일 사이드바 닫힘 및 열기 버튼으로 초점 복귀.
- [x] 게스트 메뉴 열기·Escape 닫기. 모바일 첫 Escape는 더보기만 닫고 다음 Escape는 사이드바 닫기.
- [x] 게스트 메뉴의 삭제 진입 위치 확인. 후속 F-18 구현의 실행 검증은 `F18_TEST_CHECKLIST.md` 참조.
- [x] 안내/메뉴 탐색 중 브라우저 오류 로그 없음.

## 수동 재현 체크리스트

1. 기존 Mock 실행 방법으로 앱을 열고 PC 1440×900에서 `이용 안내`를 누른다.
2. 네 단계와 주의 문구를 Figma 13과 비교한다. 예시를 눌러도 실제 대화를 만들지 않아야 한다.
3. 질문 초안을 작성하고 안내에 갔다가 뒤로가기로 돌아온다. 초안이 유지되어야 한다.
4. 안내에서 새로고침하고 학습 기록·최근 대화로 이동한다. 기존 잠금/완료 상태와 내용이 보존되어야 한다.
5. 게스트 더보기의 `전체 데이터 삭제`가 F-18 확인창으로 연결되는지 확인한다. 취소 시 데이터를 유지해야 한다.
6. 모바일 390px에서 안내를 끝까지 스크롤하고 메뉴 이동, 바깥 클릭, Tab/Escape를 확인한다.
7. Mock 시나리오 쿼리(예: `analysis=slow`)가 메뉴 이동 후에도 유지되는지 확인한다.

## F-18 연결 지점

- 전체 삭제: 게스트 더보기의 `전체 데이터 삭제` → Figma 14-1 확인 화면.
- 개별 삭제: 학습 기록 항목 더보기(Figma 14-2)의 `이 대화 삭제` → 14-3 확인 화면.
- 최신 명세는 삭제 전 되돌릴 수 없다는 확인을 요구한다. 질문·코드·생각·결과 삭제와 내용 없는 비용 기록 보존은 향후 서버 계약과 함께 구현한다.
- 후속 F-18 작업에서 Mock 삭제/확인 화면/기록 항목 더보기를 구현했다. 실제 백엔드 연결은 별도이며 상세 범위와 체크리스트는 `F18_TEST_CHECKLIST.md`에 정리했다.

## 기존 기능 회귀

전체 자동 테스트에서 질문·생각 검증, 잠금, 분석/재시도/중지, 힌트/기초 학습, 비교/회고/의견, 후속 질문, 기록 복구와 API 계약을 재검증한다. 직접 확인 항목 외 기존 모든 흐름을 수동 재실행했다는 의미는 아니다.
